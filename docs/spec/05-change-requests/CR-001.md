# Change Request: CR-001 Fix Ollama context ceiling and replace fixed source-text truncation with conditional condensation

## Request

Audio briefings read as headline-level summaries instead of explaining what stories are actually
about. Investigation traced this to two causes: (1) Ollama's context window silently defaults to
2048 tokens because `_ollama_complete` never sets `options.num_ctx`, and (2) frame and draft stages
each independently truncate every source's cleaned text to a small fixed character count (300 and
500 chars) before building their prompts, so the LLM rarely sees more than a source's opening
teaser. Fix both, using local-LLM-safe chunking (sentence-aligned, extraction-only map step) for
the rare source that's still too long once the ceiling is fixed — not blind truncation, and not a
uniform small fixed-size chunk loop.

## Final notes

- Implementation summary: Fixed `BUG-001` (explicit `num_ctx`), added `app/services/condense.py`
  with a shared 4000-char per-source budget and sentence-aligned map-step condensation for sources
  that exceed it, wired through `frame.py` → `draft.py` via `source_texts`, and tightened
  `draft.md` to require source-grounded specifics instead of generic commentary.
- Tests run: `uv run pytest -q` (full suite) — see verification table above.
- Open risks: `CONDENSE_CHUNK_CHARS`/`SOURCE_TEXT_BUDGET_CHARS` are fixed constants, not derived
  from `ollama_num_ctx` dynamically (see `ADR-001` negative consequences). Latency impact of the
  extra map-step LLM calls on long sources is not benchmarked.
- Follow-ups: none required to close this CR; revisit budget constants if `ollama_num_ctx` is
  changed significantly from its default.
