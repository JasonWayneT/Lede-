## Request

Music Roadmap Phase 3 (`docs/music/ROADMAP.md`): deterministically select a music style and asset
per drafted story from `section_name` + `sensitivity`, with a hard no-music gate for
sensitive/crisis content, a fallback for unmapped/custom sections, and a ready (if not yet
exercised) role-override path for Phase 4's future intro/outro/transition segments. See `ADR-003`
for the three design decisions this required.

## Classification

- User-visible behavior change: no (selection is computed and attached to each drafted story, but
  nothing consumes it yet — Phase 4/5 build the audio side)
- Requires new requirement ID: yes
- Requires design update: yes (`ADR-003`)
- Requires tests: yes
- Requires migration: no
- Risk level: low

## Final notes

- Implementation summary: new pure-function selection module, no new LLM call, no new pipeline
  stage. Wired into `draft.py`'s existing per-story loop, mirroring how `source_texts` was wired
  into `frame.py`/`draft.py` in `CR-001`.
- Tests run: `uv run pytest -q`
- Open risks: role-override-bypasses-sensitivity is unverified against a real structural segment
  (none exist until Phase 4) — see `ADR-003` negative consequences.
- Follow-ups: Phase 4 (audio pipeline restructuring) must create discrete intro/outro/transition
  segments before `select_music(segment_role="intro"/"outro"/"section_transition", ...)` can
  actually be called anywhere; Phase 5 (mixing) consumes `drafted_stories[i]["selected_music"]["file"]`.
