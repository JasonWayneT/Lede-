# Change Request: CR-007 Accept freeform section naming in Select stage; align QA gate with it

- Requested by: Jason Wayne
- Created: 2026-07-06
- Updated: 2026-07-06

## Request

An audit pass (`AUDIT_LOG.md`, finding P1) found that `app/pipeline/stages/select.py` no longer
classifies each story cluster against `config.sections` (the user's configured topic list) as
Story 4.6 originally specified. It now asks the LLM to invent a short freeform section name per
cluster, with no reference to `config.sections` at all. The test file already documented this pivot
in a comment, but no CR, ADR, or registry update ever recorded it, so the spec and traceability
matrix have been silently wrong since the change shipped.

Jason confirmed this was intentional and should stay: with a single real user and a content mix
that's "all over the place," picking a fixed topic taxonomy up front would mean guessing wrong.
The plan is to let the LLM freely name topics per run for now, then aggregate/average section names
across enough historical runs later to derive a real taxonomy — at which point Settings — Topic
Sections and the Select stage would be revisited together.

This CR does not change any code — `select.py` and `qa_gate.py` are already doing the confirmed
behavior. It brings `docs/spec/` back in sync with reality per this project's own documentation-first
rule, and formally supersedes the requirement that no longer describes what the system does.
