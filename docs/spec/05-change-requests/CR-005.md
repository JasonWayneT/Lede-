## Request

Music Roadmap Phase 4 (`docs/music/ROADMAP.md`): restructure audio synthesis from one
whole-briefing pass into a plan of discrete segments (intro / each story / each section transition /
outro) with known per-segment durations, so Phase 5 can mix music per segment. Preserve the single
`briefing.mp3` output contract and its non-fatal behavior. Fold in the fix for `BUG-005` (tts_prep
running on empty markdown), since the restructure rewrites that stage anyway. See `ADR-004` for the
design decisions.

## Final notes

- Implementation summary: audio synthesis is now segment-plan-based. `tts_prep` builds the plan from
  `drafted_stories` (fixing `BUG-005`), `tts.synthesize_plan` renders and concatenates it into the
  same `briefing.mp3`, and `selected_music` rides on every segment for Phase 5. No mixing yet.
- Tests run: `uv run pytest -q`
- Open risks: dropped spoken segues (see `ADR-004` negative consequences); narration quality now
  rests entirely on draft prose. Both are listening-check items, deferred to Phase 6.
- Follow-ups: Phase 5 (mixing) consumes `audio_segments[i].selected_music` + `duration_seconds`;
  decide there whether to persist per-segment audio or re-render.
