## Request

Fix `BUG-008`: `app/services/article.py` fetches arbitrary user-supplied URLs server-side with no
protection against SSRF. Add a guard rejecting non-http(s) schemes and hosts that resolve to
loopback/private/link-local/multicast/reserved addresses, applied before any outbound fetch.

## Classification

- User-visible behavior change: yes — URLs targeting internal/private addresses are now rejected (return `None`, logged as skipped) instead of being fetched
- Requires new requirement ID: no (hardens existing `FR-034`)
- Requires design update: no
- Requires tests: yes
- Requires migration: no
- Risk level: low

## Final notes

- Implementation summary: added a scheme + resolved-IP guard in `app/services/article.py`, checked
  once in `fetch_article()` before either the direct `trafilatura` fetch or the Jina Reader fallback.
- Tests run: `uv run pytest tests/services/test_article.py -q` (see task 10 of this audit pass for
  full-suite confirmation).
- Open risk: this guards DNS-resolution-time SSRF, not a DNS-rebinding attack where the hostname
  resolves safely at check time but to a different (internal) address at actual fetch time.
  Full protection against that would require re-resolving and pinning the IP used for the actual
  HTTP connection (e.g. via a custom `httpx` transport / `trafilatura` session), which is more
  invasive and wasn't judged proportionate for a single-user local tool in this pass. Flagged for a
  future hardening pass if this project moves toward "other people run this" more seriously.
