# Architecture Decision Record: ADR-003 Deterministic music style/asset selection

## Status

accepted

## Context

Music Roadmap Phase 3 needs to turn each drafted story's `section_name` (`FR-006`) and
`sensitivity` (`FR-028`) into either a music style to use, or a decision to use no music at all —
deterministically, per `docs/music/ROADMAP.md`'s V1 scope (lookup table, not a scoring engine).
Three sub-decisions needed resolving before writing the selection function.

## Decisions

**1. Segment-role overrides bypass the sensitivity gate.**
Structural segments (`intro`, `outro`, `section_transition`) always resolve to their fixed style
(`premium_newsletter_intro`, `headline_transition`) regardless of `sensitivity` — role is checked
first and short-circuits section/sensitivity logic entirely. These segments don't carry a single
story's content; they're identity/structural pieces, not a specific story's tone. This matches the
original report's own role-override design (section 13: role takes priority over topic category).
Not yet exercised end-to-end — Phase 4 hasn't built discrete intro/outro/transition segments yet —
but the logic is ready for when it does. Worth revisiting if, once Phase 4 ships, a chipper
transition immediately before a `crisis`-sensitivity story feels tonally wrong in practice; nothing
here prevents adding a sensitivity check to role overrides later if that turns out to matter.

**2. Unmapped sections fall back to `warm_daily_briefing`, not no-music.**
Lede's sections are user-editable (`FR-023` — add/rename/remove/reorder). The section→style map
only covers the four default sections (`AI`/`Technology` → `modern_tech_digest`, `Finance` →
`business_briefing`, `Politics` → `civic_affairs`, `Other` → `warm_daily_briefing`). Any section
not in that map (a custom or renamed one) falls back to `warm_daily_briefing` — matching the
original report's own fallback philosophy (`unknown_topic: warm_daily_briefing`) — rather than
silently going music-less, since an unmapped section is not a sensitivity signal.

**3. Deterministic tie-break is sorted-by-id, first match.**
`select_asset` filters candidates by style + `voice_safe`, then picks the lexicographically first
`id`. With exactly one clip per style in V1 this never actually breaks a tie — it exists so V2's
rotation/multi-candidate work (deferred, see `docs/music/ROADMAP.md`) has a stable, already-tested
selection point to extend rather than needing new logic bolted on later.

## Requirement links

- `FR-029`
- `FR-006` (section assignment, reused as the selection key)
- `FR-028` (sensitivity classification, reused as the gate)
- `FR-023` (user-editable sections — why the fallback exists)

## Consequences

### Positive

- Selection is a pure function of already-existing fields (`section_name`, `sensitivity`) — no new
  classification work needed for V1's four content styles.
- Ready for Phase 4's structural segments without redesign — `select_style` already accepts a
  `segment_role` parameter, just unused for those roles until Phase 4 creates them.

### Negative

- Role overrides bypassing sensitivity is untested against real structural segments, since none
  exist yet — this is a judgment call that may need revisiting once Phase 4 ships and it can
  actually be heard.
- `select_asset` returning `None` when no `voice_safe` candidate exists for a style is a silent
  no-music fallback, not a hard failure — correct per the "when in doubt, no music" principle, but
  means a metadata mistake (e.g. a clip incorrectly marked `voice_safe: false`) fails silently into
  "no music" rather than an visible error. Logged as a warning, not surfaced further.

### Neutral

- None.

## Alternatives considered

| Option | Why rejected |
|---|---|
| Sensitivity gate applies to all segment roles including intro/outro/transition | No structural segments exist yet to test this against; adding the check now would be speculative complexity for a scenario Phase 4 hasn't created |
| Unmapped section → no music | Treats "I don't have a style mapping for this yet" the same as "this content is sensitive," which conflates two different signals |
| Random tie-break among equal-scoring candidates | Violates the project's own determinism requirement (same input → same output, `docs/music/ROADMAP.md`'s original report §17) |
