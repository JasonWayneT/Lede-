# Known Issue: BUG-003 Gmail OAuth test exercises a function removed by the redirect-flow refactor

## Metadata

- Bug ID: `BUG-003`
- Status: fixed
- Severity: medium
- Found in: `briefing/tests/services/test_gmail.py`
- Fixed in: `CR-002`
- Related requirements: `FR-001`
- Related tests: `TEST-013`

## Current behavior

`test_authorize_stores_token_via_credentials_set` patches `app.services.gmail.InstalledAppFlow`
and calls `gmail.authorize()`. Neither exists anymore. Commit `6e0a3dd` ("Fix Gmail OAuth to use
redirect flow instead of run_local_server") removed both: `InstalledAppFlow.run_local_server()`
opens a local browser and blocks the calling thread waiting for a callback, which cannot work
inside a FastAPI request handler. It was replaced with a redirect-based flow: `build_auth_url()`
returns a Google consent URL that the browser is redirected to
(`GET /api/settings/gmail/authorize-redirect`), and `exchange_code()` exchanges the callback's
`code`/`state` for a token (`GET /oauth/callback` in `app/main.py`). That commit updated
`app/services/gmail.py`, `app/api/settings.py`, `app/main.py`, and the setup-wizard template, but
never touched `tests/services/test_gmail.py`, so the test still targets the old, deleted API and
fails with `AttributeError: <module ...gmail> does not have the attribute 'InstalledAppFlow'`.

`docs/spec/03-feature-specs/2-1-gmail-oauth-authorization.md` also still describes the removed
`InstalledAppFlow`/`run_local_server`/`gmail.authorize()` design and was never updated to reflect
the redirect flow.

## Expected behavior

The test suite covers the OAuth mechanism the app actually ships: `build_auth_url()` producing a
consent URL, and `exchange_code()` exchanging the callback code for a token and storing it via
`credential_store.set()` — the same storage guarantee the deleted test verified, just against the
current entry point.

## Unchanged behavior

- No application code changes — `app/services/gmail.py`'s redirect flow (in production since
  `6e0a3dd`) is correct and unaffected. This is a test + spec fix.
- Token storage contract is unchanged: still `credential_store.set(GMAIL_OAUTH_TOKEN, token_json)`,
  never written to a file.

## Reproduction steps

1. Run `uv run pytest -q tests/services/test_gmail.py::test_authorize_stores_token_via_credentials_set`.
2. Observe `AttributeError: <module 'app.services.gmail' ...> does not have the attribute 'InstalledAppFlow'`.
3. Confirm neither `InstalledAppFlow` nor `authorize` appear in `app/services/gmail.py` (`git grep` returns nothing).

## Root cause

`tests/services/test_gmail.py` and `docs/spec/03-feature-specs/2-1-gmail-oauth-authorization.md`
were never updated after the OAuth mechanism was intentionally replaced in `6e0a3dd`.
