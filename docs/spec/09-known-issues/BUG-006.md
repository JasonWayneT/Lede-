# Known Issue: BUG-006 Dashboard doesn't surface a held run's failure reason

## Metadata

- Bug ID: `BUG-006`
- Status: fixed
- Severity: medium
- Found in: `briefing/app/main.py` (`dashboard` route), `briefing/app/templates/dashboard.html`
- Fixed in: (direct fix, lightweight bug-fix workflow — no CR)
- Related requirements: `FR-014`, `FR-021`
- Related tests: `TEST-018`

## Current behavior

The dashboard route (`GET /`) only queries for a run with `status == "running"` to decide whether
to show the live progress bar. It never checks for a run in `status == "hold"` (a failed run
awaiting manual retry, per `FR-014`). So when a run fails — e.g. Ollama unreachable — the dashboard
silently falls back to its idle view, showing the stale "Up to date / Last run {old date}" banner
from the last *successful* run, with no indication anything is wrong. The failure reason (`run.error`)
is only visible on the History page, which the user has no reason to check unless they already know
something failed.

Discovered live: two runs (`run_id` 4 and 5) went into `hold` with
`[select] Ollama unreachable: All connection attempts failed`, and the dashboard continued to show
"Last run Tuesday, June 30" with no hint that today's runs had failed.

## Expected behavior

When a run is in `hold` state, the dashboard shows a clear banner with the failure reason and a
retry action — the same information already correctly tracked in the database and displayed on
History, surfaced on the page the user actually lands on.

## Unchanged behavior

- History page's existing hold/error/retry display is unchanged.
- The retry endpoint (`POST /api/briefings/{run_id}/retry`) and hold/retry mechanics (`FR-014`) are
  unchanged.
- The live SSE-driven "running" progress view is unchanged.

## Reproduction steps

1. Stop Ollama (or otherwise make a stage fail retryably).
2. Trigger a run; let it exhaust retries into `hold`.
3. Load or reload the dashboard (`/`).
4. Observe: idle banner shows the last *successful* run, no mention of the held run or its error.

## Root cause

`main.py`'s `dashboard()` handler queries only `Run.status == "running"` (line ~96) and passes
nothing about held runs to the template; `dashboard.html`'s status bar only has `#status-idle` and
`#status-running` variants — no hold variant, despite `badge-hold`/`alert-error` CSS already
existing in `theme.css` unused for this purpose.
