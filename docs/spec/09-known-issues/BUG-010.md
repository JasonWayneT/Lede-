# Bug: BUG-010 Gmail service silent failures

## Metadata

- Bug ID: `BUG-010`
- Severity: High
- Status: fixed
- Found: 2026-07-06 (audit pass, findings R1/R2)
- Fixed: 2026-07-06

## Description

Two related silent-failure paths in `app/services/gmail.py`:

1. **`_lookback_query`** read `data/settings.json` to get the configured ingest lookback window,
   wrapped in a bare `except Exception: pass`. Any parse failure (corrupted file, wrong type)
   silently fell back to a 7-day window with no log line and no user-facing signal — a user could
   set a custom lookback window, have the settings file get corrupted, and never know their setting
   silently stopped applying.
2. **`get_credentials_path`** raised a raw `FileNotFoundError` (not a `StageError`) when
   `credentials.json` is missing, reachable from `build_auth_url`/`exchange_code` mid-OAuth-flow.
   The two current callers in `api/settings.py` happened to catch `FileNotFoundError` specifically,
   but any other caller (a new route, a future pipeline path) would let it escape uncaught —
   inconsistent with this project's convention of raising `StageError` from service/stage code so
   failures always carry a `stage_name`/`retryable`/`code` shape callers can rely on.

## Impact

- (1) A misconfigured/corrupted lookback setting silently narrows which emails get ingested, with
  no way for the user to notice.
- (2) Inconsistent error shape from a service function; low risk today since existing callers
  happen to catch the specific exception type, but fragile against future callers.

## Root cause

Both are missing-logging / inconsistent-error-type gaps rather than logic bugs — the fallback
behavior itself (7-day default; clear failure message) was already reasonable, it just wasn't
visible or consistently typed.

## Fix

1. `_lookback_query` now logs a `WARNING` (with the settings path and the underlying exception)
   before falling back to the 7-day default, and the `int(...)` parse is now inside the same
   try/except so a non-numeric `lookback_days` value is caught too, not just JSON parse errors.
2. `build_auth_url` and `exchange_code` now catch `FileNotFoundError` from `get_credentials_path`
   and re-raise as `StageError("gmail_oauth", ..., retryable=False, code=AUTH_ERROR)`. The two
   callers in `api/settings.py` (`authorize_redirect`, `reauthorize_gmail`) were updated to catch
   `StageError` instead of the old `FileNotFoundError`. `main.py`'s `/oauth/callback` handler
   already caught bare `Exception` and needed no change.

## Regression tests

`tests/services/test_gmail.py`: `test_build_auth_url_raises_stage_error_when_credentials_missing`,
`test_exchange_code_raises_stage_error_when_credentials_missing`,
`test_lookback_query_logs_warning_on_corrupt_settings`,
`test_lookback_query_uses_configured_days_when_settings_valid`.
