# Known Issue: BUG-005 tts_prep runs on empty markdown (stage-ordering data dependency)

## Metadata

- Bug ID: `BUG-005`
- Status: fixed
- Severity: high
- Found in: `briefing/app/pipeline/stages/tts_prep.py` + `briefing/app/pipeline/orchestrator.py` STAGES order
- Fixed in: `CR-005`
- Related requirements: `FR-010`, `FR-030`
- Related tests: `TEST-016`

## Current behavior

`tts_prep.py` builds its prompt from `packet.assembled_markdown`
(`prompt_template.format(assembled_markdown=packet.assembled_markdown)`). But `assembled_markdown`
is written **only** by the `assemble` stage, which runs at position 9 in `STAGES` — *after* `tts_prep`
at position 8. So when `tts_prep` runs, `assembled_markdown` is still its empty-string default. The
TTS narration script is therefore generated from an empty briefing: the LLM is asked to convert
nothing, and downstream audio synthesis (`tts.synthesize(packet.tts_script, ...)`) runs on whatever
the model returns for empty input — effectively no real briefing content.

## Expected behavior

The narration script and pronunciation guide are derived from the actual drafted story content, so
the synthesized audio contains the real briefing.

## Unchanged behavior

- Audio failure remains non-fatal to the run (`FR-011`).
- The final audio artifact is still a single `briefings/{run_id}/briefing.mp3` at the same path.
- The text/markdown briefing (`assemble` → `markdown_path`) is unaffected.

## Reproduction steps

1. Run the pipeline to completion.
2. Inspect the `stage_08_tts_prep.json` handoff artifact: `tts_script` reflects an empty-input
   conversion, not the assembled stories.
3. The generated `briefing.mp3` does not narrate the briefing content.

## Root cause

Data-dependency inversion in `STAGES`: `tts_prep` (8) consumes a field produced by `assemble` (9).
`tts_prep` read the wrong upstream source — it should derive narration from `drafted_stories`
(produced by `draft` at stage 7, always available before stage 8), not from the not-yet-populated
`assembled_markdown`.

## Fix

`CR-005` rewrites `tts_prep` to build the narration/segment plan from `packet.drafted_stories`
instead of `packet.assembled_markdown`, removing the dependency on a later stage entirely. See
`docs/spec/07-decisions/ADR-004.md` and `docs/spec/03-feature-specs/6-4-audio-segment-plan.md`.
