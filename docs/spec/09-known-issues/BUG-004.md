# Known Issue: BUG-004 test_app_config_defaults asserts a stale ollama_model_name default

## Metadata

- Bug ID: `BUG-004`
- Status: fixed
- Severity: low
- Found in: `briefing/tests/test_config.py`
- Fixed in: `CR-002`
- Related requirements: `ARCH-002`
- Related tests: `TEST-002`

## Current behavior

`test_app_config_defaults` asserts `config.ollama_model_name == "llama3.2"`. Commit `b2626a4`
("Portfolio polish: README rewrite + model upgrade") intentionally changed
`AppConfig.ollama_model_name`'s default from `"llama3.1:8b-instruct-q5_K_M"` to
`"qwen2.5:7b-instruct-q4_K_M"` for better JSON-following behavior, but never updated this
assertion (which — notably — didn't even match the pre-upgrade default either; `"llama3.2"` was
never the value of this field in this codebase).

## Expected behavior

The test asserts the default that `AppConfig` actually ships with.

## Unchanged behavior

- No application code changes — `AppConfig.ollama_model_name` default is correct and intentional.
  This is a test-only fix.

## Reproduction steps

1. Run `uv run pytest -q tests/test_config.py::test_app_config_defaults`.
2. Observe `AssertionError: assert 'qwen2.5:7b-instruct-q4_K_M' == 'llama3.2'`.

## Root cause

`tests/test_config.py` was never updated after `b2626a4` changed the default Ollama model.
