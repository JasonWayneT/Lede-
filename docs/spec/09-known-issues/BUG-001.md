# Known Issue: BUG-001 Ollama context window silently capped at 2048 tokens

## Metadata

- Bug ID: `BUG-001`
- Status: fixed
- Severity: high
- Found in: `briefing/app/services/llm.py` (`_ollama_complete`)
- Fixed in: `CR-001`
- Related requirements: `FR-015`, `FR-007`, `FR-008`, `ARCH-006`
- Related tests: `TEST-009`

## Current behavior

`_ollama_complete` posts to `/api/generate` without an `options.num_ctx` value. Ollama silently
defaults `num_ctx` to 2048 tokens for any model, regardless of what the model actually supports.
The configured default model (`qwen2.5:7b-instruct-q4_K_M`) natively supports 32K tokens, but every
Ollama-routed prompt — frame, draft, and now condense — was implicitly capped at 2048 tokens shared
across system prompt, source text, and generated output. Combined with the frame/draft stages'
own 300/500-character source-text truncation (see `FR-027`), this left very little effective budget
for real source content, producing generic, headline-level drafted stories.

## Expected behavior

`_ollama_complete` explicitly sets `options.num_ctx` from `AppConfig.ollama_num_ctx` (default 8192)
on every request, so the model's real context window is used intentionally rather than silently
truncated by an Ollama client default.

## Unchanged behavior

- Request shape for non-Ollama providers (OpenAI, Anthropic, Gemini, MCP sampling) is unaffected.
- `llm.complete()` public signature is unchanged.

## Reproduction steps

1. Run a briefing with `llm_provider=ollama` and a multi-paragraph source article longer than ~2000
   tokens once combined with prompt scaffolding.
2. Inspect the Ollama request body sent by `_ollama_complete` — no `options` key is present.
3. Ollama truncates context to 2048 tokens for the call regardless of the configured model's real
   capability.

## Root cause

`_ollama_complete` (briefing/app/services/llm.py:45-58) builds the request body with only
`model`, `prompt`, and `stream` — it never sets `options.num_ctx`. Ollama's HTTP API defaults
`num_ctx` to 2048 when the field is absent from `options`.
