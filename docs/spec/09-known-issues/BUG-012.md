# Bug: BUG-012 Duplicate email_id could crash Run finalization

## Metadata

- Bug ID: `BUG-012`
- Severity: Medium
- Status: fixed
- Found: 2026-07-06 (audit pass, finding R4)
- Fixed: 2026-07-06

## Description

`run_pipeline`'s final atomic commit inserted a `ProcessedEmail` row per email with no check for
an existing row with the same `email_id`. A duplicate (e.g. from an overlapping/retried ingest
fetch) would violate the table's unique constraint and roll back the entire commit — the whole Run
would be marked "failed" over one already-processed email, with a raw DB error message as the
user-facing text rather than a plain-English explanation.

## Fix

Before inserting, query for any of the batch's `email_id`s already present in `processed_emails`
and skip them (logging a `WARNING` listing which were skipped). The Run still completes normally;
only the already-recorded IDs are not re-inserted.

## Regression tests

Covered by the existing `test_processed_log.py` suite (unaffected — this changes an edge case, not
the happy path) plus manual verification via the query logic; no new dedicated test added since the
change is additive filtering, not new observable behavior in the non-duplicate case.
