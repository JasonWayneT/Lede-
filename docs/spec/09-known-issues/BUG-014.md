# Bug: BUG-014 Corrupt music file took out audio for the whole briefing

## Metadata

- Bug ID: `BUG-014`
- Severity: Medium
- Status: fixed
- Found: 2026-07-06 (audit pass, finding R6)
- Fixed: 2026-07-06

## Description

`mixing._load_music()` handled a *missing* file gracefully (falls back to no music), but a
*present-but-corrupt/zero-length* file raised uncaught from `soundfile.read`, propagating through
`mix_story`/`mix_structural` into `synthesize_plan`, which catches it at the top level and turns it
into a non-fatal `StageError` — but that means the run loses audio entirely, for every segment, over
one bad clip, rather than just the one segment that referenced it.

## Fix

Wrapped the `soundfile.read` call in a `try/except Exception`, degrading to "no music for this
segment" (same as the missing-file path) with a `WARNING` log, isolating the failure to the one
segment instead of the whole briefing's audio.

## Regression tests

`tests/services/test_mixing.py`: `test_corrupt_file_story_falls_back_to_dry_voice`,
`test_corrupt_file_structural_returns_none`.
