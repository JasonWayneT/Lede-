# Bug: BUG-016 Gemini errors classified by fragile string matching

## Metadata

- Bug ID: `BUG-016`
- Severity: Medium
- Status: fixed
- Found: 2026-07-06 (audit pass, finding R10)
- Fixed: 2026-07-06

## Description

`_gemini_complete` classified auth failures by lowercasing the exception string and
substring-matching `"api key"`/`"permission"`/`"unauthenticated"`. Any unrelated Gemini SDK error
whose message happened to contain those substrings — or a wording change in a future SDK version —
would be silently misclassified as a non-retryable `AUTH_ERROR`, potentially masking a genuinely
retryable transient failure.

## Fix

Catch the SDK's own typed exceptions (`google.api_core.exceptions.Unauthenticated`,
`PermissionDenied`) for the `AUTH_ERROR` case, matching the pattern already used for OpenAI
(`openai.AuthenticationError`) and Anthropic (`anthropic.AuthenticationError`). Everything else
falls through to the existing generic `PROVIDER_UNAVAILABLE`/retryable branch.

## Regression tests

`tests/services/test_llm.py`: `test_gemini_permission_denied_raises_auth_error`,
`test_gemini_unrelated_error_does_not_misclassify_as_auth_error` (the latter uses an error message
that *contains* the old trigger words to prove the new code no longer keys off message content).
